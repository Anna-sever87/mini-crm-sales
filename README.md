# Mini CRM Sales

Локальная мини-CRM для обычных продаж. Данные: клиенты, сделки, задачи. Сервер на FastAPI, база SQLite. Пользовательская авторизация Google проходит на компьютере; ключ и токен находятся в `.secrets`.

## Возможности

- Три вкладки: клиенты, сделки, задачи. Добавление, редактирование, удаление, поиск и фильтрация по статусу.
- Выбор клиента и сделки из списков, архивирование клиента, отметка выполнения задачи.
- Сохранение данных в SQLite между перезапусками контейнера.
- Генерация вымышленных данных через API, по умолчанию по 1000 записей каждого вида.
- Выгрузка текущего списка каждой вкладки в отдельную Google Таблицу с итогами и оформлением.
- Открытие созданного отчёта и папки отчётов в браузере.

Для работы нужны Docker Desktop и Python 3.12 с tkinter. Интерфейс работает на компьютере, сервер — в Docker. Google-авторизация выполняется на компьютере, ключ и токен не передаются в контейнер.

## Запуск сервера

Из корня проекта:

```powershell
docker compose up --build -d --wait
docker compose ps
```

Проверка: `http://localhost:8000/health`. Страница команд Swagger: `http://localhost:8000/docs`.

Порт доступен только на текущем компьютере. База сохраняется в `data/crm.db`; папка `data` подключается к контейнеру отдельно. Изменения кода сервера автоматически подхватываются Uvicorn.

Остановка с сохранением базы:

```powershell
docker compose stop
```

## Разделы API

- `/clients` — клиенты: создание, просмотр, редактирование, удаление; статусы `active`, `archived`.
- `/deals` — сделки: сумма в рублях, клиент, ожидаемая дата завершения; статусы `new`, `in_progress`, `won`, `lost`.
- `/tasks` — задачи: клиент и/или сделка, срок; статусы `todo`, `done`.
- `/stats` — количество записей, суммы и распределение по статусам.
- `/health` — состояние сервера и доступность базы.

Списки поддерживают `search`, `status`, `limit`, `offset`. Сделки дополнительно фильтруются по `client_id`, задачи — по `client_id` и `deal_id`. Поиск русских названий работает без учёта регистра.

Удаление клиента сохраняет его сделки и задачи, очищая связь с клиентом. Удаление сделки сохраняет задачи, очищая связь со сделкой. Перед удалением реальных записей удобнее использовать архивирование клиентов, если нужно сохранить историю отношений.

Суммы хранятся в базе целым числом копеек. API возвращает суммы строками с двумя десятичными знаками. Средняя сумма считается отдельно от общей и округляется до копейки.

## Авторизация Google

Нужны включённые Drive API и Sheets API, OAuth-клиент типа Desktop app и тестовый пользователь в Google Cloud. В Data Access выбирается разрешение `https://www.googleapis.com/auth/drive.file`.

Скачанный JSON хранится как `.secrets/oauth-client.json`. Установка библиотек и вход:

```powershell
.\.venv\Scripts\python.exe -m pip install --no-cache-dir -r requirements.txt
.\.venv\Scripts\python.exe authorize_google.py
```

Токен сохраняется в `.secrets/token.json`. Содержимое `.secrets`, `.venv` и рабочая база исключены из Git.

На новом компьютере сначала создайте окружение: `python -m venv .venv`.

## Окно CRM и учебные данные

После запуска сервера и установки библиотек откройте окно:

```powershell
.\.venv\Scripts\python.exe crm_app.py
```

Или выберите конфигурацию «Окно CRM» в VS Code и запустите без отладки.

Для заполнения учебными данными выполните в другом терминале:

```powershell
.\.venv\Scripts\python.exe fill_test_data.py --count 1000
```

Скрипт добавляет по 1000 клиентов, сделок и задач. Имена, компании, контакты и сделки вымышленные. Повтор с той же меткой `--batch` дополняет недостающие записи; уже существующие учебные и другие записи сохраняются. В окне CRM после заполнения нажмите «Обновить данные».

Скрипт использует только API сервера и не обращается к файлу базы напрямую. Ключи и токены Google для заполнения базы не нужны.

## Выгрузка отчётов

На нужной вкладке задайте поиск и статус и нажмите «Найти» или «Обновить данные». Затем нажмите «Выгрузить отчёт». В отчёт попадает именно загруженный и показанный список, а не скрытые фильтром записи.

При первой выгрузке на Google Диске автоматически создаётся папка `Mini CRM Sales Reports`. Её ID сохраняется локально в `config.local.json`. Каждый экспорт создаёт новый файл. Права доступа к другим файлам и настройки общего доступа программа не изменяет.

Отчёт содержит заголовок, дату создания, описание фильтра, три итоговых показателя, распределение по статусам и все строки выбранного списка. Средняя сумма сделки рассчитывается по тем же строкам, что показаны в отчёте. Для пустого списка средняя не подменяется нулём.

После записи программа читает контрольные ячейки. Сообщение об успешной выгрузке появляется после проверки количества записей и последней строки. Кнопка «Открыть отчёт» открывает полученную ссылку.

При ошибке сети проверьте папку отчётов перед повтором: файл мог успеть создаться. Если Google-аккаунт изменился или папка удалена, потребуется проверить сохранённую папку и авторизацию.

## Основные файлы

- `backend/database.py`, `backend/models.py`, `backend/main.py` — база, поля и API.
- `compose.yaml`, `backend/Dockerfile` — запуск сервера в Docker.
- `crm_client.py` — обращения окна и тестового заполнения к API.
- `crm_app.py`, `gui/` — настольное приложение и формы.
- `fill_test_data.py` — создание учебных записей через API.
- `google_integration/auth.py` — вход и сохранение токена.
- `google_integration/google_drive.py`, `google_integration/google_sheets.py` — CRUD и оформление файлов Google.
- `report_data.py`, `reports.py` — расчёты, подготовка и проверка отчётов.

## Проверка API на временной базе

```powershell
.\.venv\Scripts\python.exe -m pip install --no-cache-dir -r requirements-dev.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты проверяют CRUD, связи, сохранение записей, поиск, суммы и ошибочные данные. Рабочая база и Google Диск при этом не меняются.

Дополнительно проверяются повторное заполнение без дубликатов, расчёты отчётов, просроченные задачи и отсутствие ложного сообщения об успехе при ошибке проверки выгрузки. Эти автоматические проверки не заменяют создание и открытие трёх настоящих отчётов в своём Google-аккаунте.

## Сдача домашнего задания

Приложите ссылку на GitHub и скриншоты: запущенный контейнер, CRM с записями, папку с тремя видами отчётов и открытые отчёты с итогами. Перед публикацией проверьте состав коммита: `.secrets`, `.venv`, `.checks`, `config.local.json` и рабочая база должны быть исключены.
